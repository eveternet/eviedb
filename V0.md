# EvieDB v0

v0 exists to answer one question:

> **Can a useful typed relational persistence system feel native to TypeScript without introducing SQL or another query language?**

## Success criterion

A developer should be able to install EvieDB, create one `db.ts`, define a small related schema, persist data, restart the application, retrieve and modify that data, deliberately use table scans or indexes, maintain basic constraints, and perform useful relational work using ordinary TypeScript.

No SQL should be required anywhere in that path.

## Candidate capabilities

The proof of concept is expected to need some version of runtime schema definitions with TypeScript inference; tables and typed rows; a small set of scalar codecs; CRUD; primary keys; uniqueness and nullability constraints; explicit indexes and index maintenance; basic referential integrity if needed; persistence across restarts; and writes safe enough that the demonstration is not based on obviously corruptible happy-path behavior.

This is a direction, not a frozen checklist. Features should exist because the proof of concept needs them, not to imitate another database's feature table.

## Explicitly not required

v0 does not need SQL parsing, an EvieDB query DSL, automatic query planning, SQL-style `JOIN` or `UNION` syntax, remote networking, EvieTCP, arbitrary server-side computation, a binary/page storage engine, a WAL unless the durability model requires one, sophisticated concurrency, multi-process access, a migration framework, analytical query features, production performance, or production stability.

## Before implementation

Several API choices remain intentionally unsettled. In particular, schema declarations, table access, mutations, indexes, and persistence semantics should be decided enough that implementation tests a coherent idea rather than discovering the product accidentally.

The design documents should change as those decisions become real.

Until then, examples are sketches.

**Do not let an illustrative method name become architecture by copy-paste.**
